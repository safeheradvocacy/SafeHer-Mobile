F-09 — Clickjacking Proof of Concept

SafeSpace Security Assessment · Finding F-09: missing X-Frame-Options and CSP frame-ancestors

If the SafeSpace administrative dashboard renders in the frame below, the application can be embedded by any third-party origin, confirming F-09. If the frame stays blank or shows a refusal message, the framing protection is working.
What this demonstrates.

A page under an attacker's control can load the SafeSpace admin dashboard inside an invisible or disguised iframe. Because an administrator's session cookie travels with the framed request, the attacker can overlay decoy UI and trick an authenticated administrator into clicking real controls — approving a verification, reassigning a case, revoking an access token — while believing they are interacting with the attacker's page. This is clickjacking (UI redress).

A real attack would set opacity: 0 and position the frame beneath a decoy button. This PoC leaves the frame fully visible and interactive controls untouched, because the point is to evidence the framing, not to exercise any action against the live system.

Live target: https://safespace-administrative.vercel.app/
Framed by:

Two different origins. No same-origin exception applies — if this renders, the only thing that could have stopped it was a response header, and there isn't one.

Remediation to verify against.

Add to admin/vercel.json, redeploy, then reload this page. The frame should go blank. 

{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }],
  "headers": [{
    "source": "/(.*)",
    "headers": [
      { "key": "X-Frame-Options",         "value": "DENY" },
      { "key": "Content-Security-Policy", "value": "frame-ancestors 'none'" },
      { "key": "X-Content-Type-Options",  "value": "nosniff" },
      { "key": "Referrer-Policy",         "value": "strict-origin-when-cross-origin" },
      { "key": "Permissions-Policy",      "value": "camera=(), microphone=(), geolocation=(self)" }
    ]
  }]
}
