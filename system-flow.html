System Requirements

System Flow

The sequence each primary SafeSpace process actually follows end to end, from the initiating actor's action through the system's processing to the resulting outcome. Mirrors the workflows already shown in the Use Case Diagram and Context Diagram, expressed here as an ordered sequence rather than a static relationship.

Table 6

System Flow

Flow Step Actor Action / System Process
Account Registration
& Verification		 1 Survivor / Reporter Submits personal information and a PSGC-based registered address (municipality, barangay, purok/sitio) through the mobile app.
2 System Validates all required fields, creates the account through Supabase Auth, and provisions the linked survivor profile.
3 Survivor / Reporter Optionally submits an identity-verification document from the Profile screen.
4 Municipal / Provincial Admin Reviews the submitted document and approves or rejects the verification request.
Incident Report
Submission		 1 Survivor / Reporter Completes the incident report form (case type, incident details, location) and submits it.
2 System Validates the submission, generates a case number, and determines case ownership (barangay, municipal, or provincial) based on routing rules.
3 System Notifies the responsible administrator(s) that a new case has been filed.
4 Barangay / Municipal / Provincial Admin Reviews the case, updates its status, and assigns it as needed.
5 System Logs each status change to the case history and notifies the survivor of the update.
Emergency SOS 1 Survivor / Reporter Triggers the Emergency SOS button and confirms the alert.
2 System Captures the device's real-time location and creates an SOS alert record.
3 System Delivers the alert to the police dashboard in real time via Supabase Realtime, with an audible and visual alert.
4 Police Officer Acknowledges the alert and responds, updating its status as the situation is addressed.
5 Police Officer Creates a law-enforcement referral linked to the alert when further action is required.
Shelter Request
& Referral		 1 Survivor / Reporter Browses available shelters and submits a shelter request, or an administrator refers an existing case to a shelter.
2 System Routes the request or referral to the selected shelter's administrator.
3 Shelter Administrator Reviews the request or referral and accepts or declines it.
4 System Updates the request/referral status and notifies the requesting survivor or case owner of the outcome.
Case Referral
& Escalation		 1 Barangay / Municipal Admin Reviews a case within their jurisdiction and determines it requires escalation or referral.
2 Barangay / Municipal Admin Refers the case to a higher administrative tier or to law enforcement, with a stated reason.
3 Receiving Admin / Police Officer Reviews the referral and responds, accepting ownership or taking the requested action.
4 System Records the referral outcome in the case's status history for full traceability.
Administration
& System Management		 1 Provincial Admin Creates and manages user accounts, municipality/barangay/shelter reference data, and system-wide settings.
2 System Enforces each account's authorized role and jurisdiction through Row-Level Security on every request, independent of the interface.
3 Municipal Admin / Provincial Staff Generates reports and reviews audit logs for oversight and accountability.

Every status change and referral in these flows is recorded to the relevant history table, giving each case and SOS alert a complete, auditable timeline.
