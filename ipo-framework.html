Figure 1. Conceptual Framework of the Study

Input–Process–Output model with feedback, showing the development and evaluation of SafeSpace.

INPUT

Knowledge requirements

  • Reporting and case-handling workflow in Aurora Province (preliminary consultations)
  • RA 9262, RA 7610, RA 11313, RA 11930, RA 10173
  • NPC Circular No. 2023-06
  • Nine user roles and their jurisdictional scopes
  • PSA Philippine Standard Geographic Codes
  • Review of related literature
  • ISO/IEC 25010:2023 quality model

Software requirements

  • React Native with Expo (mobile)
  • React with Vite (web dashboard)
  • TypeScript
  • Supabase — Auth, PostgreSQL with Row Level Security, Storage, Realtime, Edge Functions
  • Vercel (web hosting), Expo EAS (mobile builds)
  • Google Maps and Groq APIs
  • Git and GitHub

Hardware requirements

  • Computers for development and administration
  • Android devices for testing and deployment
  • Internet connection

Mobile delivery is Android; iOS is configured but not built.

PROCESS

Iterative and incremental development

  1. Gathered and analyzed requirements
  2. Designed the baseline: database schema, RLS policies, and user interface
  3. Built one module at a time — a new function, a refinement, or a correction
  4. Verified each increment: type checks, production builds, and live database queries
  5. Corrected gaps before beginning the next increment

Steps 3–5 repeated for every module

  1. Integrated the mobile application and the web platform

Security assessment

  • Static review of source, migrations, and dependencies
  • Live testing of the deployed system: authorization boundaries, transport security, and the mobile artifact
  • Findings classified by severity and remediated by priority

Evaluation

  • ISO/IEC 25010:2023-based questionnaires administered to IT professionals and end users
OUTPUT
SafeSpace A Mobile and Web-Based Abuse Reporting and Response System for Aurora Province

Mobile application — survivors

  • Submit abuse reports with evidence
  • Send SOS alerts with live location
  • Consult the AI support assistant, with handoff to a human expert
  • Locate and request shelter
  • Track case status and receive notifications

Web platform — nine authorized roles

  • Review, assign, and escalate cases
  • Monitor and dispatch SOS alerts
  • Manage shelter referrals and occupancy
  • Coordinate police referrals
  • Verify identity and walk-in case access
  • Generate reports and analytics
  • Maintain audit logs and system backups

Data protection

  • Role-based access control across administrative levels
  • Row Level Security enforced on every table

Evaluation results

  • Assessments by IT professionals and end users
  • Identified strengths and areas for improvement

Feedback. Verification findings guided corrections within each increment; security assessment results directed remediation; and evaluation results informed refinements and recommendations.
